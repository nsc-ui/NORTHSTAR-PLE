# NORTHSTAR-PLE

**Verification-first autonomous engineering agent harness** for Google's Physical-Engineering's Last Exam (PLE). This project targets the PLE task protocol and uses a Google-sponsored model endpoint; no credentials are stored in source.

## Design

NORTHSTAR combines a time-aware model/tool loop with evidence-led engineering workflow:

- Recursive workspace reconnaissance and deliverable/acceptance matrix.
- Source traceability, explicit assumptions, unit/dimensional checks, and reproducible calculations.
- Task-local MCP tool discovery and schema-guided search/call; Streamable HTTP session reuse, JSON/SSE response parsing, pagination.
- Shell and file tools for calculations, document extraction, code, CAD/BIM, and validations available inside task containers.
- Adaptive retries, error feedback to the model, a final skeptical verification pass, and a non-destructive workspace audit.
- Long-history context compaction that preserves task instructions, progress ledger, recent tool cycles, and token usage.
- Time-budget reserve and cancellation handling; no outside web APIs or grader access.

## Selected model

`submission.yaml` currently targets `google-cloud/gemini-4-neon`. This is a provisional experiment choice based on the public PLE leaderboard snapshot, not an assertion that this model/harness combination has been benchmarked by NORTHSTAR. The model selection should be tested against another eligible model using controlled dev runs.

## Official evaluation (requires the competition kit, Docker, accepted HF dataset access, and a local model proxy)

```bash
uv run python -m kit check ../NORTHSTAR-PLE --cancel-test
uv run python eval/run.py ../NORTHSTAR-PLE
uv run python -m kit artifacts ../NORTHSTAR-PLE
uv run python eval/run.py --artifacts ../NORTHSTAR-PLE
```

Follow the official kit guide for setup and dataset access. `artifacts/` must be generated by the official runner; NORTHSTAR intentionally does not synthesize or fabricate it. When a genuine run exists, populate the CSVs in `analysis/` and regenerate figures.

## Docker (local container)

Prerequisites: Docker Engine with the Compose plugin.

1. Copy the safe configuration template:
   ```bash
   cp .env.example .env
   ```
2. Build and start the websocket server:
   ```bash
   docker compose up --build -d
   ```
3. Check status and logs:
   ```bash
   docker compose ps
   docker compose logs -f northstar
   ```
4. Stop it:
   ```bash
   docker compose down
   ```

The service listens on `ws://localhost:8000` by default (or the host port set by
`PLE_PORT`). The image runs as an unprivileged user. The container only packages
the NORTHSTAR WebSocket server; it does **not** install the official PLE kit,
run the official evaluator, grant gated dataset access, or provision the model
proxy. Those integrations require the official environment and credentials.

For local checks without starting the service:
```bash
docker build -t northstar-ple:local .
docker run --rm northstar-ple:local python scripts/check_entry.py
docker run --rm northstar-ple:local python tests_unit.py
docker run --rm northstar-ple:local python tests_context.py
docker run --rm northstar-ple:local python tests_cancel.py
docker run --rm northstar-ple:local python tests_smoke.py
```

Do not put tokens in the Dockerfile, image, or committed `.env`. When the
official proxy integration provides its credential mechanism, use its prescribed
secret injection. Docker Compose secrets are mounted as files under
`/run/secrets/<secret-name>` and should be preferred for supported integrations.

## Phase 1 benchmark integration

The `benchmark/` directory provides the safe local integration layer for the pinned official PLE kit. It includes the 29-task manifest, kit bootstrapper, prerequisite checks, dry-run launcher, result analyzer, experiment log template, and run instructions. The official evaluator is kept outside this submission in `.ple-kit/`; credentials belong only in the ignored `benchmark/local.env`.

See [`benchmark/README.md`](benchmark/README.md) for setup, dry-run, diagnostic, full-run, regrade, and failure-triage commands. No benchmark scores or official artifacts are generated by these helper files.
